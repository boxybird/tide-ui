Microinteractions worth the attention

  1. Open and return as one continuous journey. Carry the event title or date from its card into the full-screen view; reveal the photo alongside it. Return to the same card, filters and scroll position, with sensible keyboard focus. Use ordinary navigation when View Transitions are unavailable.
  2. Make saving unmistakable. Immediate filled-bookmark state and a short “Saved” confirmation. A removal can offer Undo. If persistence fails, restore the previous state and explain the failure. Saving must not also open the event.
  3. Give every tap a quiet response. A small surface or foreground change on press, visible keyboard focus, and generous invisible hit areas around small icons. Keep the touching cards visually stable.
  4. Make filter changes legible. Show active choices and the new result count. Update smoothly while keeping the controls stable. No matches should offer a direct way to widen the date or clear filters.
  5. Confirm completed actions honestly. “Link copied” only after a successful copy. Cancelling a share sheet is ordinary behavior. Label calendar actions as adding or downloading an event; do not claim a calendar entry was saved when that cannot be verified.
  6. Let loading settle quietly. Keep image space and controls in place as an image appears. A failed image should resolve to the approved texture without a layout jump. Use a calm placeholder rather than an endlessly animated shimmer.

Proposed starting motion tokens: 100–150 ms for press/save feedback and roughly 220–280 ms for navigation. These are design choices to test on a phone, not standards. Honor reduced-motion preferences and ensure navigation remains usable with motion disabled. Announce relevant feedback to assistive technology without moving focus.

The next three focused studies

  1. Save, open, return. Demonstrate saved state, brief confirmation, correct Back behavior and the same list position. This is the smallest interaction slice with the most immediate payoff.
  2. Plans changed. Show the same event as sold out, rescheduled and cancelled, including the correct action and explanatory text.
  3. Information or connection missing. Show no photo, long content, no filter matches and a recoverable network failure.

Keep each study separate from the approved baseline. Static HTML can show these state designs; a small isolated interactive demonstration is needed to judge timing, persistence and return behavior. Event reviews, social feeds and notification systems can wait until there is a clear user need.

Accessibility and evidence limits

The inspected views visibly maintain clear hierarchy and readable text over both sample photos. This run does not establish WCAG conformance. It did not test a screen reader, text enlargement, every image/background combination, live save requests, actual ticketing, real offline behavior or motion on a physical phone. Verify keyboard focus, focus return, accessible bookmark state, status announcements, reduced motion and responsive text during implementation. Use text alongside color for important event states.

The present files are deliberately static design studies. Unimplemented saved/search/booking behavior is a scope limit, not a regression. Research below informs recommendations and is separate from the fresh screenshot evidence.
