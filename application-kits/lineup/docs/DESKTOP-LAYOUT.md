# Desktop composition · Lineup 2.2.3

In Lineup 2.1.8 the event photo's return link hides from 60rem, where the list and detail appear side by side. Below that breakpoint it remains a native link to all events on full-screen event documents. Private application hosts control availability; the optional Saved action retains its existing position and appearance. An otherwise empty toolbar is omitted. Event/pane dimensions and the story's lower return link remain unchanged. See the current [design QA](../design-qa.md).

The [selected compact-header implementation](COMPACT-HEADERS.md) replaces the previous browse intro and The lineup kicker with two utility rows. The user separately authorized the small Tide 1.11.0 Results variant and accepted both that recipe and the application change on 2026-10-27.

At 75rem and above, CSS Grid/subgrid preserves the centered 92rem maximum and 20/35/45 filters/list/detail proportions. The left Search & Filters label and middle count/order header start at the same top edge as the natural right document. Both labels consume canonical `tide-results--utility`. The Search Events label and first month title align below their dividers. Lineup's external summary gap is 8px; Tide's unchanged calendar header adds 8px before its title. The feed therefore starts 8px above the filter body, while their first labels share the same position. The application owns placement only, with no public type, padding, color or divider overrides. Mobile and tablet now use the same 8px utility-summary gap. Native fragment reservation shares this private gap input; filter-column geometry remains unchanged.

`workspace-browse.html` owns the private two-column browse frame and desktop-only utility label. `lineup-summary.html` owns the permanent result heading, optional venue information jump and order label. The count is h1 on collection pages and a secondary h2 on native event pages; those retain their event h1. The inline `results-title` helper adds Albuquerque/venue context for accessibility. The count and its context remain outside the popover at every width. The original Results region and feed remain focusable.

The complete isolated feed sits below its permanent summary in `.tide-app__feed-scroll`. Native scrollbar gutters, Grid rows and viewport units bound the two left panes with at least 24px bottom clearance. The right document scrolls naturally. Venue context adds its information jump below the count, with a matching private allowance in the adjacent utility-label row. No browser height measurements or JavaScript are needed.

Below 75rem, the desktop utility label is hidden and Filters opens the original non-modal left popover. Its canonical drawer header/title, one form/control set, scrolling body and pinned footer remain. Native Close/Escape/outside dismissal, focus return and Reset are browser-owned. CSS slide/reduced-motion rules are unchanged. Widening an open drawer uses the existing CSS anchor to fit its reserved desktop column; the shared geometry remains the fallback. See the [drawer contract](FILTER-DRAWER.md).

From 60rem to 75rem, the count stays above the bounded feed beside the detail document. There is no marketing intro occupying a separate row. The page header still budgets a canonical 48px Filters control in that split range, with 44px for ordinary navigation-only/desktop rows. Phone presents the count above the feed. Full-screen phone event reading retains the original event h1 and hides the browse workspace.

Saved retains its existing local Page intro, default Results row and bounded feed in three explicit rows. Its two desktop tracks remain columns 1/2 without an unused leading track. Help and submission retain their existing content layouts. These surfaces do not gain a filter launcher.

Native month IDs/links remain. The feed keeps zero target padding; the outer document reserves the canonical utility row and external gap, plus venue context where present. Saved reserves its own local intro and default result row. Month targets align to the feed top without shifting the outer desktop document. Tide owns all calendar typography, padding and borders.

The filter footer retains its direct-child Tide recipe and canonical status/count/reset layout. Existing private child wrappers preserve narrow drawer safe-area clearance and outward field focus-ring space. Result data, exact event/venue IDs and all native paths are unchanged.

Current browser and source evidence is in [compact headers](COMPACT-HEADERS.md) and [design QA](../design-qa.md). The earlier [Tide alignment](TIDE-ALIGNMENT.md), [Saved/type repair](SAVED-TYPOGRAPHY.md), [heading/venue repair](HEADINGS-VENUE-SCOPE.md) and [footer/tablet repair](FILTER-FOOTER-TABLET.md) remain historical evidence for their original states. Chromium on Windows with viewport emulation is current coverage; other engines, physical devices and screen readers remain unverified.

Native links, history, controls and validation remain; search matching, persistence and service operations remain outside scope as documented in [handoff](HANDOFF.md).
