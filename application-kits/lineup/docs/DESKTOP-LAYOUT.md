# Desktop composition · Lineup 2.0.5

The entire app is native HTML/CSS with no browser scripts. At 75rem and above, authored filter/list/detail columns use CSS Grid/subgrid in 20/35/45 proportions after gaps, inside a centered 92rem maximum. The heading and controls start in their final column; no node moves during load.

`workspace-browse.html`, `workspace-results.html`, `filter-rail.html`, `filter-status.html` and `filter-actions.html` own the complete structure. The result summary is outside `.tide-app__feed-scroll`, which contains the complete isolated feed, empty state and footer. CSS grid rows reserve the summary naturally; month headings stick at the feed top without measuring its height. Native gutter reservation replaces JavaScript scrollbar measurement. Left panes remain bounded with a minimum 24px bottom clearance; the right document scrolls naturally.

Below 75rem, Filters opens the same authored panel as a left-side native popover drawer. The browser owns toggling, Close, Escape, outside-click dismissal and focus return; CSS owns placement, slide transitions, reduced motion and the bounded scrolling body/pinned footer. At desktop widths the panel stays visible even when the popover is closed. An open popover resized to desktop fits its reserved column through CSS anchor positioning, with shared grid geometry as a fallback. Native dismissal then returns it to ordinary flow without hiding the column. No controls move or duplicate. Saved keeps its separate layout; event details retain full-screen reading at phone widths. See the [drawer contract and verification](FILTER-DRAWER.md).

The filter footer keeps the compact quiet Reset button on the left and the authored page event count on the right in two CSS grid tracks at every width. The button retains the shared hover/focus styling and native form reset; changing controls does not update the authored count. Longer count text can wrap inside its right track without moving below Reset.

At 60rem and above, Saved's results section has three explicit rows: intrinsic intro, intrinsic summary and the remaining bounded feed. Other result sections have only the summary and bounded feed. An intro must not occupy the summary's flexible row or push the feed into an implicit track. Saved now places its list/detail in the two explicit columns 1/2, without an unused first or implicit third track. Its list is 352px at 1200px and 390px from 1440px; browse pages retain their scoped columns 2/3.

Native month IDs and links remain unchanged. App-owned `.tide-lineup__month` removes the kit's general target margin, and the feed's own scroll padding is zero. While a month is targeted, the outer document reserves the private context wrapper and canonical one-line Results row, in addition to its normal sticky inset. Saved reserves its canonical Page intro instead of that context wrapper. Results/calendar typography, padding and borders remain kit-owned. This prevents the old month remaining above the target and avoids moving the desktop right document to compensate for the summary. Keep this token-based offset consistent with any future summary rhythm changes; no measured browser inputs are used. Below 60rem there is no sticky page header or permanent summary to reserve, so month fragments have no extra target gap. Other fragments retain their existing spacing.
