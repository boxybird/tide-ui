The rules that hold it together

Extensions inherit the visual structure of the original.

  1. 24px page insets. Cards meet edge to edge, with fine dividing rules.
  2. Dots belong to event surfaces. Forms and reading areas stay calm and plain.
  3. One primary accent per task. Secondary actions use an outline or a text link.
  4. 48px form controls; 44px icon targets. Radius: 2px fields, 2px actions, 4px documentation panels.
  5. Visible labels and focus rings. Meaningful status words accompany every status color.
  6. Long titles wrap. Missing facts stay unknown. A poor photo never carries the reading hierarchy.

05 / Tokens

Names that describe the job.

Components consume stable semantic roles. Mode-specific values live behind those roles, so the HTML stays the same.

Three levels, one direction

  1. Primitives set fixed font, spacing, radius, target and border rules.
  2. Semantic roles describe canvas, content, actions, selection and status.
  3. Component tokens alias those roles only when a component needs a documented extension point.

A mode is not a theme

Tide, Summer and Bumble are themes. Light, dark and system are appearance modes. Choose each independently on the root element.

<html lang="en" data-theme="tide" data-mode="dark">
  <body class="tide">…</body>
</html>

06 / Themes

3 themes. 6 considered modes.

A theme may change colors and texture strength. Type, spacing, corners, structure and control sizes remain fixed.

LightDark

Apricot surfaces and plum in daylight. Warm charcoal and peach after dark.

LightDark

The background is part of the contract

A new canvas seed regenerates its surfaces, readable text, control edges, status text and focus colors. The compiler measures the actual foreground/background pairs before writing CSS.

Normal text ≥ 4.5:1. Meaningful control edges and focus ≥ 3:1. Decorative panel rules are intentionally quieter.

System appearance, without JavaScript

Use data-mode="system", or omit data-mode. Native color-scheme and light-dark() follow the device preference. Explicit light or dark overrides it.

07 / Extend

A repeatable way to grow.

Add a theme or a component without editing the existing component definitions or changing the selected visual foundation.

Add a theme

  1. Add a named entry in tokens/themes.json, including light and dark canvas/accent seeds.
  2. Run python tools/build.py. Surfaces and foregrounds are resolved together.
  3. Review both modes, all states and the contrast report. Commit source and generated CSS together.

The gate rejects missing modes, duplicate names, invalid colors and failing pairs. A direct CSS override bypasses that guarantee.

Add a component

  1. Use a new BEM block: .tide-panel, its elements and explicit modifiers.
  2. Consume the existing semantic roles and spacing tokens. Add a new role only when no existing role fits.
  3. Put the addition in a later component layer; document its states and add a fixture in every theme/mode.

Example: a new panel, with no core mutation

@layer tide.components.extensions {
  .tide-panel {
    --tide-panel-background: var(--tide-color-surface);
    --tide-panel-padding: var(--tide-space-6);
    display: grid;
    gap: var(--tide-space-3);
    padding: var(--tide-panel-padding);
    border: var(--tide-border-hairline);
    border-radius: var(--tide-radius-panel);
    background: var(--tide-panel-background);
    color: var(--tide-color-text-primary);
  }
}

Open the working panel example. Keep new rules inside the named layer. Do not override a theme with component selectors.
