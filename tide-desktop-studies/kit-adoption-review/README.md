# Search and filters — adoption review

[Read the review](http://127.0.0.1:4187/kit-adoption-review/index.html) · [Approved prototype](http://127.0.0.1:4187/margin-reveal-unified-search/demo/index.html) · [Existing adoption rules](http://127.0.0.1:4187/base/kit/docs/ADOPTION.md)

Recorded 2026-10-24 against kit 1.2.1 and approved Unified Search 1.0.2. This is an additive documentation review, not a component release. The existing 180 maintained-kit files and 72 approved-prototype files remain unchanged. No runtime styles, scripts, primitives, themes, public manifest or approved dependencies are edited.

The review recommends one new layout block, `tide-filter-panel`, for a scrolling body and pinned footer. Its count/status row and actions belong to that block rather than becoming separate components. Query, dates, categories, launchers, badges, applied context, errors and recovery reuse existing components. Shared interaction contracts cover draft versus applied state, one submit, Reset all, modal Cancel, applied Clear all, focus and responsive restoration. Dataset matching, routing, desktop column geometry and scrollbar measurement stay host-owned.

`decisions.json` is the machine-readable review register. Proposed names and source homes are deliberately separate from the maintained kit's shipped `component-manifest.json`; none are represented as implemented. `templates/review.html` and `build.py` generate the readable `index.html` using the kit's existing Prose and Content page. The HTML example at `examples/combined-form.html.txt` uses shipped controls; it is a form contract, not a working search service.

This is companion documentation for `tide-responsive-app/kit/`, not another kit implementation. Both that kit's exact file inventory and the approved prototype are preservation-locked. Adding documentation inside the locked directory would invalidate those inventories even if no CSS changed. The future versioned adoption can integrate these contracts into `kit/docs/SEARCH-FILTERS.md` and the existing component/navigation registry.

Run Python `-B build.py` to regenerate the review, then `-B check.py`. Verification checks source references and existing component reuse, the approved prototype/archive, the complete preserved dependency chain and the existing maintained-kit inventory. Kit build/check/unittests run against a temporary copy so their reports cannot overwrite frozen evidence. `qa/` holds this review's evidence. Original Firefox/Safari testing remains deferred at the user's request; no new accessibility or cross-browser certification is claimed.

Actual extraction belongs in a later additive kit release and an unfrozen app consumer together: add shared CSS/HTML/all-theme specimens, register the public block, remove corresponding app duplicates and compare geometry. Keep this approved prototype and its current dependency URLs pinned. Link this review from the main kit navigation during that release; the existing navigation has not been rewritten just to add a documentation link.
